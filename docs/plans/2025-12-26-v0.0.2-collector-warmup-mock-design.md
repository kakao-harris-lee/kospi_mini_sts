# v0.0.2 Design: Collector Lightweighting, Warm-up, Mock Prediction

**Date:** 2025-12-26
**Status:** Approved
**Author:** Claude Code

---

## Overview

This design addresses three issues in the current pipeline:

1. **Collector Double Load**: ClickHouse I/O in the Collector can block Redis publishing during DB delays
2. **Cold Start Z-Score**: OFI Z-scores are inaccurate for the first 100 ticks after restart
3. **No LSTM Model**: Pipeline testing blocked by missing prediction model

---

## Architecture

### Current Flow
```
WebSocket → Collector → ClickHouse (blocking)
                     → Redis Stream (fire-and-forget)
```

### New Flow (v0.0.2)
```
WebSocket → Collector → Redis Stream only (fire-and-forget)
                              ↓
                    ┌────────┴────────┐
                    ↓                 ↓
            FeatureProcessor    RawDataLogger
            (warm-up on start)  (→ ClickHouse)
                    ↓
            MockPredictionEngine
                    ↓
            StrategyManager
```

## Component 1: Collector Lightweighting

**File:** `src/collector/tick_collector.py`

### Remove
- `orderbook_inserter` (BatchInserter for orderbook_snapshots)
- `trade_inserter` (BatchInserter for trade_ticks)
- `init_tables()` call
- ClickHouse-related imports from `src.common`

### Keep
- `_redis_publisher` - publish raw tick data to `RAW_DATA_STREAM`
- WebSocket connection and tick parsing logic
- Metrics recording (tick counts, websocket status)

### Result
- Collector becomes a pure fire-and-forget publisher
- ~150 lines removed
- Zero ClickHouse dependency
- No blocking I/O in the hot path

## Component 3: OFI Warm-up

**File:** `src/processor/feature_processor.py`

### Problem
`OFICalculator` uses `deque(maxlen=100)` for Z-score calculation. On restart, the deque is empty, causing Z-scores to be zero or inaccurate for the first 100 ticks.

### Solution
Add `warm_up()` method to load historical data from ClickHouse on startup.


### Integration
```python
class FeatureProcessor(StreamConsumer):
    def __init__(self):
        super().__init__(...)
        # Warm-up on init
        self._warm_up_symbols()

    def _warm_up_symbols(self):
        """Warm up OFI calculators for known symbols"""
        symbols = ["101V24", "A05601"]  # From config or auto-detect
        for symbol in symbols:
            state = self._get_state(symbol)
            count = state.ofi_calc.warm_up(symbol)
            logger.info(f"Warm-up: {symbol} loaded {count} OFI records")
```

## Component 4: MockPredictionEngine

**File:** `src/prediction/mock_engine.py` (New)

### Purpose
**For testing and backtesting only.** Not for production paper/live trading.

Use cases:
- Pipeline integration testing (verify data flows end-to-end)
- Backtesting strategy logic without LSTM dependency
- Development environment testing

### Signal Generation Modes

#### Mode 1: Random (default)
```python
def _generate_random(self) -> tuple[float, float, float]:
    """Random probabilities with slight bias toward hold"""
    hold = random.uniform(0.3, 0.5)
    up = random.uniform(0.2, 0.4)
    down = 1.0 - hold - up
    return up, down, hold
```

#### Mode 2: MA Cross
```python
def _generate_ma_cross(self, features: dict) -> tuple[float, float, float]:
    """Based on MA5 vs MA20 ratio"""
    ma_ratio_5 = features.get('ma_ratio_5', 1.0)
    ma_ratio_20 = features.get('ma_ratio_20', 1.0)

    if ma_ratio_5 > ma_ratio_20 * 1.001:  # Golden cross
        return 0.6, 0.2, 0.2
    elif ma_ratio_5 < ma_ratio_20 * 0.999:  # Death cross
        return 0.2, 0.6, 0.2
    else:
        return 0.33, 0.33, 0.34
```

#### Mode 3: OFI-based
```python
def _generate_ofi_based(self, features: dict) -> tuple[float, float, float]:
    """Based on OFI Z-score"""
    ofi_z = features.get('ofi_z_score', 0.0)

    if ofi_z > 1.5:
        return 0.7, 0.15, 0.15
    elif ofi_z < -1.5:
        return 0.15, 0.7, 0.15
    else:
        return 0.3, 0.3, 0.4
```

### Output Format
Same as real `PredictionEngine`:
```python
{
    'symbol': str,
    'timestamp': float,
    'up_prob': float,      # 0.0 ~ 1.0
    'down_prob': float,
    'hold_prob': float,
    'model_version': "mock_v1",
    'inference_time_ms': float
}
```

### Configuration

## Rollback Plan

If issues arise:
1. Re-enable ClickHouse in Collector (revert tick_collector.py)
2. Disable RawDataLogger service
3. Warm-up failure is non-fatal (logs warning, continues with empty deque)
